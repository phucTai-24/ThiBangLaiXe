## 4. Adoption direction

This documentation pack is inspired by a well-structured CMS project, but it is rewritten for the context of this project.

That means:
- do **not** copy Node.js or TypeScript-specific concepts directly,
- keep the standardization mindset: clear documentation, layered architecture, consistent API responses, dedicated validation, and explicit development workflow,
- make every example fit the current **ASP.NET Core Web API / .NET / SQL Server** stack.

## 5. Scope of this documentation version

This version primarily targets:
- Backend: **ASP.NET Core Web API / .NET 8 / EF Core / SQL Server**
- Frontend: the current web application, with room for future mobile support
- Core business scope: theory practice exams, critical questions, exam templates, random exam generation, wrong-question review, traffic signs, and content administration

## 6. Practical recommendation

The current project appears to be in a stage where authentication, data scaffolding, and some UI structure already exist, while business modules are still incomplete or only partially standardized.

This documentation pack is meant to help the team move forward in a more professional and maintainable way:
- easier onboarding,
- clearer task assignment,
- better code review,
- more reliable AI-assisted development,
- more business-like project continuity.
